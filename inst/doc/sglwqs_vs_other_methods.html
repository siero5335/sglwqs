# Extract weights
# Extract weights from groupWQS
extract_weights_groupwqs <- function(fit, var_names, group_list, method_name = "groupWQS") {

  # Get GLM coefficients (excluding Intercept)
  glm_coefs <- coef(fit$fit)
  gwqs_coefs <- glm_coefs[grep("^GWQS", names(glm_coefs))]
  
  # Get weights
  weights_list <- fit$weights
  
  # Data frame to store results
  result <- data.frame()
  
  for (i in seq_along(weights_list)) {
    grp_weights <- weights_list[[i]]
    grp_coef <- gwqs_coefs[i]
    
    # Determine direction based on coefficient sign
    if (grp_coef >= 0) {
      direction <- "Positive"
    } else {
      direction <- "Negative"
    }
    
    df_grp <- data.frame(
      variable = names(grp_weights),
      weight = as.numeric(grp_weights),
      direction = direction,
      method = method_name,
      stringsAsFactors = FALSE
    )
    
    result <- rbind(result, df_grp)
  }
  
  return(result)
}

weights_groupwqs <- extract_weights_groupwqs(gwqs_group_fit)

Scalability and Computational Efficiency

SGL-WQS is designed for large-scale epidemiological studies with robust engineering:

Batched Parallel Processing

SGL-WQS employs a batched parallelization strategy with memory management, enabling efficient bootstrapping even for large cohorts (N = 100,000) on standard workstations.

Automatic memory management: When data exceeds 100MB, SGL-WQS automatically adjusts the future.globals.maxSize setting to prevent worker errors.

library(sglwqs)
library(future)

plan(multisession, workers = 10)

# For large datasets, sglwqs auto-detects and adjusts memory settings
fit <- sglwqs(
  X = large_data[, exposures],  # e.g., N = 100,000
  y = large_data$outcome,
  groups = groups,
  family = "binomial",
  bootstrap = TRUE,
  n_boot = 500,
  parallel = TRUE,
  validation = TRUE,
  checkpoint_dir = "sglwqs_checkpoint",    # Save progress periodically

  # future_globals_max_size = NULL,         # Auto-detect (default)
  # future_globals_max_size = 2000 * 1024^2,  # Or specify manually: 2GB
  seed = 123
)

Comparison with Other Methods

In our testing with N = 100,000 and 500 bootstrap iterations:

Method Memory Usage Crash Recovery Completion
gWQS High (all in memory) No May fail
qgcomp High No May fail
groupWQS High No May fail
SGL-WQS Managed (batched) Yes Stable

Key advantages: - Memory management: Results saved to disk periodically, reducing memory pressure - Crash recovery: Resume from checkpoint if interrupted - Progress monitoring: Check completed iterations via checkpoint file - Configurable data transfer: future_globals_max_size prevents worker errors

Recommended Settings by Data Size

N < 10,000 500 Optional 4-8 < 30 min
N = 10,000-50,000 500 Recommended 8-10 1-2 hours

N = 100,000 500 Required 10+ 3-5 hours

Note: Times are approximate and depend on hardware, number of exposures, and complexity.
